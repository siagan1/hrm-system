# HRM 운영 가이드 (서버 PC 배포 · 업데이트 · 백업)

## 핵심 원칙: 코드와 데이터는 따로 움직입니다

| 구분 | 위치 | 옮기는 방법 |
|---|---|---|
| 코드 | 프로젝트 폴더 (git으로 관리) | 개발 PC → git push → 서버 PC `git pull` |
| 데이터 | 서버 PC의 `C:\hrm-data\hrm.db` (프로젝트 폴더 **밖**) | **옮기지 않음.** 최초 1회만 개발 PC의 DB를 복사 |
| 스키마 변경 | `prisma/migrations/` (코드와 함께 git으로 이동) | 서버에서 `prisma migrate deploy`가 아직 안 된 것만 적용 |

- DB 파일은 `.gitignore`에 들어 있어 git으로 절대 넘어가지 않습니다.
- 서버 PC의 DB를 프로젝트 폴더 밖에 두므로, 코드를 통째로 다시 받아도 데이터는 그대로입니다.
- **서버 데이터 → 개발 PC 복사는 괜찮지만(테스트용), 개발 PC DB → 서버 복사는 최초 1회 이후 절대 금지**입니다. 팀장들이 입력한 데이터가 덮어써집니다.

## 서버 PC에서 절대 실행하면 안 되는 명령

| 명령 | 이유 |
|---|---|
| `npx prisma migrate dev` | 스키마 차이를 감지하면 DB 초기화(전체 삭제)를 제안합니다 |
| `npx prisma migrate reset` | DB를 비우고 처음부터 다시 만듭니다 |
| `npx prisma db push` | 마이그레이션 이력 없이 스키마를 강제로 맞춥니다(데이터 손실 가능) |
| `npm run seed` | 등급 기준 개월수를 기본값으로 덮어쓰고, 안 쓰는 팀·기본 계정(공개 비밀번호)·샘플 프로젝트를 만듭니다 |
| `npm run dev` | 개발 모드. 느리고 운영용이 아닙니다 |

서버에서 스키마를 바꾸는 유일한 명령은 `npx prisma migrate deploy`(업데이트 스크립트가 실행)입니다.

## 최초 설치 (서버 PC, 1회)

1. **설치:** Node.js(LTS, 개발 PC와 같은 메이저 버전), Git for Windows
2. **코드 받기:** `git clone <저장소 주소> C:\hrm-system`
3. **데이터 폴더 만들기:** `C:\hrm-data\`
4. **현재 데이터 옮기기:** 개발 PC에서 `npm run backup -- 서버이전` → 생성된 백업 파일을 서버의 `C:\hrm-data\hrm.db`로 복사
5. **`.env` 작성** (`C:\hrm-system\.env`, git에 안 올라감):
   ```
   DATABASE_URL="file:C:/hrm-data/hrm.db"
   AUTH_SECRET="<새로 생성: npx auth secret 또는 32바이트 랜덤 문자열>"
   AUTH_TRUST_HOST=true
   BACKUP_DIR="C:/hrm-data/backups"
   BACKUP_COPY_DIR="<다른 저장소, 예: D:/hrm-backup 또는 OneDrive 폴더>"
   ```
   - `AUTH_TRUST_HOST=true`가 없으면 운영 모드에서 IP 주소로 접속 시 로그인이 거부됩니다.
   - `AUTH_SECRET`은 개발 PC와 다른 값을 쓰세요.
6. **설치·빌드:** `npm ci` → `npx prisma migrate deploy` → `npx prisma generate` → `npm run build`
7. **Windows 서비스 등록** (NSSM 사용, 이름 `HRM`): 프로그램 `npm.cmd`, 인자 `run start`, 시작 폴더 `C:\hrm-system`, 시작 유형 자동
8. **방화벽:** 인바운드 TCP 3100 허용 (사내 네트워크 프로필만)
9. **노트북 전원 설정:** 절전·최대 절전 끄기, 덮개를 닫아도 아무 작업 안 함
10. **고정 IP:** 공유기에서 서버 노트북 IP를 고정(DHCP 예약). 팀장 전달 URL: `http://<고정IP>:3100`
11. **계정:** 관리자 계정 비밀번호를 기본값(`admin1234!`)에서 반드시 변경. 시드로 만든 `manager@`/`user@` 계정은 삭제하거나 비밀번호 변경
12. **백업 예약:** 아래 "백업" 참고

## 업데이트 (개발 PC → 서버 PC)

개발 PC:
1. 기능 개발 → 스키마를 바꿨다면 마이그레이션 생성(`CLAUDE.md` 5번 절차)
2. 새 마이그레이션의 `migration.sql`을 열어 `DROP COLUMN`·데이터 삭제가 의도한 것인지 확인
3. 커밋 → push

서버 PC (관리자 PowerShell, 사용자가 적은 시간에):
```
cd C:\hrm-system
powershell -ExecutionPolicy Bypass -File scripts\update-server.ps1
```
스크립트 순서: 코드 받기 → 적용될 마이그레이션 확인(y 입력) → 서비스 중지 → **DB 백업** → 패키지 설치 → 마이그레이션 적용 → 빌드 → 서비스 시작. 중단 시간은 보통 2~5분입니다.

## 백업

- 명령: `npm run backup` (서버가 켜져 있어도 안전한 온라인 백업 + 무결성 검사)
- 라벨 백업: `npm run backup -- 배포전` → 자동 삭제되지 않음
- 보관 정책(정기 백업): 최근 30일은 전부, 그 이전은 월별 1개씩 12개월
- 저장 위치: `BACKUP_DIR`, 그리고 `BACKUP_COPY_DIR`가 있으면 2차 사본도 저장
- **같은 디스크에만 있는 백업은 노트북 고장·분실 시 같이 사라집니다.** `BACKUP_COPY_DIR`는 외장 디스크·NAS·OneDrive처럼 다른 저장소로 지정하세요.

**자동 백업 예약** (서버 PC, 관리자 PowerShell, 1회):
```
$action  = New-ScheduledTaskAction -Execute "npm.cmd" -Argument "run backup" -WorkingDirectory "C:\hrm-system"
$trigger = New-ScheduledTaskTrigger -Daily -At 12:30pm
Register-ScheduledTask -TaskName "HRM 일일 백업" -Action $action -Trigger $trigger -User "SYSTEM" -RunLevel Highest
```
점심시간처럼 노트북이 확실히 켜져 있는 시각으로 잡으세요. 하루 2회가 필요하면 트리거를 하나 더 추가합니다.

**점검:** 한 달에 한 번 백업 폴더에 최근 파일이 쌓이고 있는지 확인하고, 분기마다 최근 백업을 개발 PC에서 복구해 열어 보세요(복구 연습).

## 문제가 생겼을 때

**데이터를 잘못 입력/삭제했다 → 백업 시점으로 되돌리기**
1. `Stop-Service HRM`
2. `npm run restore -- C:\hrm-data\backups\hrm-YYYYMMDD-HHMMSS.db` (복구 직전 상태를 `복구전` 라벨로 자동 보관)
3. `Start-Service HRM`
- 백업 이후에 입력된 데이터는 사라집니다. 팀장들에게 해당 시간대 입력분 재입력을 요청하세요.

**업데이트 후 문제가 생겼다 → 이전 버전으로 되돌리기**
1. `Stop-Service HRM`
2. `git reset --hard <이전 커밋>` (업데이트 스크립트가 출력한 값)
3. 이번 업데이트에 마이그레이션이 있었다면 `npm run restore -- <'업데이트전-…' 백업>`
4. `npm ci` → `npx prisma generate` → `npm run build` → `Start-Service HRM`
